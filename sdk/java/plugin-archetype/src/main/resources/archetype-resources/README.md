# ${artifactId}

This `${interface}` Plugin Program project was generated by the Tenon Plugin Archetype.

**Files to edit**

- `src/main/java/${packageInPathFormat}/Main.java`: Configure the SDK entrypoint and any custom initialization.
#if ($interface == "source")
- `src/main/java/${packageInPathFormat}/SourcePluginFactory.java`: Create upstream clients, send Source payloads, and map acknowledgements back to the upstream protocol.
- `src/main/proto/source_record_payload.proto`: Define the Source business record.
#elseif ($interface == "sink")
- `src/main/java/${packageInPathFormat}/SinkPluginFactory.java`: Create downstream clients, handle ordered batches, and complete each result at the documented success boundary.
- `src/main/proto/sink_record_payload.proto`: Define the Sink business record.
#else
- `src/main/java/${packageInPathFormat}/SourceAndSinkPluginFactory.java`: Implement Source production and Sink writes using shared connections or resources.
- `src/main/proto/source_record_payload.proto` and `src/main/proto/sink_record_payload.proto`: Define the two independent payload roots in the one Program descriptor.
#end
- `src/main/tenon/config.schema.json`: Define connections, credentials, and stable runtime options shared by this Program. Do not put per-message data here or use `default`.
- `pom.xml`: Add business compile/runtime dependencies. Keep the one `tenon-plugin-sdk` dependency. Set `tenon.displayName` and `tenon.description` for Console. Both require nonblank plain text: the single-line name allows 1-80 Unicode code points; the description allows 1-1024 and LF/CR line breaks. The bundler validates and preserves these values.

Flow `parallelism` is the number of ordered Pipeline channels, not the number of producers. Sink `write` receives non-empty, ordered, immutable batches and may have multiple asynchronous results in flight.

Use stdout and stderr for diagnostics. Tenon supplies the plugin's startup configuration; do not read business input from stdin.

**Build**

```shell
./mvnw package
```

This command runs the tests and creates a self-contained Plugin Program package for the current operating system and CPU under `target/`. The package carries its own Java runtime and does not depend on a system JVM.
